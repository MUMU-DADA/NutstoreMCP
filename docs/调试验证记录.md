# 调试验证记录

验证日期：2026-10-09。范围：C1 普通文件移动/重命名、C2 单目录创建、E4 只读路径 ACL，以及写入保护条件。只用客户端自己的实现和既有会话。

## 一、实验边界

- 原有云端和本地数据不作为写操作靶子；本轮源文件、冲突哨兵、目录和下载目标均为专门新建。
- 使用现有 `mcp-test` 沙箱：ID `<sandbox-id>`，magic `<magic>`。已确认真实绑定根 `%USERPROFILE%\Nutstore\1\mcp-test`。
- 外部本地输出使用新目录 `%USERPROFILE%\NutstoreTest\phase-c916b61b8d6a`。不在客户端管理的 `Nutstore\1` 树内创建新绑定目标。
- 先用桥验证入口和冲突语义，再固化专用接口并合并部署。未测试删除或 ACL 修改。
- 令牌创建使用 `FileMode.CreateNew`，拒绝覆盖已有令牌，`finally` 移除本次创建的令牌。验证结束确认没有残留 `l3-write*.enabled`。

原始脚本/输出保存在工作区忽略目录 `.test-tmp/`，包括 `fixtures.json`、`move-collision-result.json`、`move-success-result.json`、`mkdir-collision-result.json`、`mkdir-success-result.json`、`path-acl-result.json`、`live-cloud-test.ps1` 和 `live-cloud-results.json`。它们是本机证据，不是仓库中可依赖的已提交文件；关键结果在下文保留。

## 二、桥实验及正确入口

### C1 普通文件移动

旧 `ca22f644cc5eac05e5c099fb105c5b6f5(src,dest,IEnumerable<WriteMetaDataParams>)` 是目录批量入口，空集合违反前置条件。之前的 `ArgumentException` 不能说明普通文件移动不可用。

正确文件入口：

```csharp
cfa4bff2b588c3bab781ef7189ef94b90(NutstorePath destination, NutstoreObject source)
// source: NutstoreObject+Builder.FileBuilder(src, 0L, 0L, size, version, hash).Build()
```

原始客户端调用尝试移动到新建哨兵路径，返回 `DuplicateName/Conflict`；源和哨兵保持原状态。随后移动到全新 `/stage-963023562060-renamed.txt` 成功。专用工具进一步移动到新建目录中的 `moved.txt`。

### C2 单目录创建

入口 `cfd1df8451110086567f3d56edf4697e8(NutstorePath)`。原始调用对已有哨兵文件返回 `DuplicateName/Conflict`，哨兵仍是文件，版本 1、大小和哈希不变。创建全新 `/stage-963023562060-directory` 成功，目录版本 1、大小 0。

### E4 ACL 读取

入口 `c5c78b21a991a876d4bd8093b70f39202(NutstorePath) -> SubPathAcl`。未调用 ACL 修改方法。专用工具显式映射继承状态、权限和成员，不序列化客户端会话对象。
