## 一、这个项目是什么

把坚果云桌面客户端**只能在 GUI 上操作**的能力做成 MCP 工具。
插件以 mod 形式放进客户端目录即生效，开关在客户端自己的设置界面里。

**两条硬约束（用户明确要求，不可违背）**：

1. **绝不导致数据丢失。** 这是用户反复强调的绝对约束。
2. **只用客户端自己的实现。** 不引入需要申请第三方凭据的接口
   （如 WebDAV 应用密码）—— 那违背「装上插件就能用」的初衷。

## 二、调试「修改类」操作的注意事项 ⚠️

### 2.1 测试一律用新建的目录和文件（用户明确要求）

> 「涉及到修改的操作 都使用新创建的目录和新创建的文件来进行测试
>  不要动云端和本地原有的目录和文件」

具体做法：

- **云端靶子**：新建的沙箱 `mcp-test`（id `<sandbox-id>`，
  magic `<magic>`）
- **本地靶子**：该沙箱绑定的目录 `%USERPROFILE%\Nutstore\1\mcp-test`
- **只读地引用已有文件是允许的** —— 读不改东西

### 2.2 写操作必须有守卫

已经验证生效的模式：

```
未解锁          → 拒绝（令牌文件 %LOCALAPPDATA%\NutstoreMcp\l3-write.enabled）
没有 confirm    → 拒绝
dryRun（默认）  → 只预演，不执行
最后一道        → 实际操作前后核对真实状态，不信任调用方
```

**「实际操作前核对真实状态」这条最要紧**：`nutstore_l3_move` 会
**真的列出云端目录**核对源存在、目标不存在 —— 而不是相信调用方说的。

### 2.3 两道锁，不是一道

- `l3-write.enabled` —— 普通写入
- `l3-write-system.enabled` —— **系统级设置**（会装文件系统驱动、
  影响权限验证的那几个）

分开的理由：共用一把锁的话，「为了改开机自启而解锁」
就等于同时允许装驱动。

### 2.4 破坏性操作宁可不做

`ForbiddenClientMethods` 有 9 条禁止调用清单。
**删除（`cd9ad552f919`）建议不做** —— 收益小、风险极高。

### 2.5 失败是不是干净的，要实测

已观察到客户端**在动手前先校验完参数**：

- 传 null 给移动方法的第三参数 → 抛异常，**移动没有发生**
- 移动因 `ArgumentException` 失败 → **文件仍在原处**

这两次都是干净的失败。但**不要假设所有失败都干净** ——
每次改完都用只读接口复查真实状态。

## 五、基础设施与工具（省时间的部分）

### 5.1 改钩子必然要重启客户端

钩子跑在客户端**默认域**，.NET Framework 卸不掉默认域已加载的程序集。
已确认无替代路径（WPF 对象和 `ServiceLocator` 的活对象都在默认域）。

**所以：加能力只改插件侧（可热重载），别改钩子。**
非改不可时，用手上的**通用反射桥**先验证，攒够了再一次性固化 + 重启。

### 5.2 一条命令做「停 → 装 → 起」

```powershell
.\deploy\restart-client.ps1
```

会自己处理三件事：

- **先停 `nutstore_watchdog`** —— 否则杀掉客户端会被它立刻拉起来，
  永远等不到「已退出」
- 安装提权是**异步**的，脚本靠**轮询程序目录的契约**判断装完没有
- 启动用**计划任务**（跑在 DSH 沙箱外），否则命名管道起不来、
  资源管理器角标会坏
- **起来后再等 12 秒复查** —— 「进程出现过」不等于「进程活着」，
  犯过这个错，代价是用户的同步停了一段时间

⚠️ **加了新钩子方法后，要同步更新脚本里的 `$required` 清单** ——
否则轮询会拿旧契约立刻通过。

### 5.3 日常命令

```powershell
.\verify.ps1                       # 构建 + 212 测试 + 13 探针 + 11 配置补丁
.\deploy\build.ps1                 # 只构建 + 部署插件（热重载，不重启客户端）
dotnet run --project src/NutstoreMcp -- --doctor         # 独立服务器自检
dotnet run --project src/NutstoreMcp -- --dump-config-keys
```

MCP 端点：`http://127.0.0.1:17321/mcp`

### 5.4 反编译工具链

类型名和方法名**都是哈希**，按语义名字搜永远搜不到 ——
落空的表现是「看起来没这个能力」，而不是报错。**这个假象误导了好几轮。**

```powershell
ilspycmd -p -o <输出目录> "C:\Program Files\Nutstore\bin-7.2.12\NutstoreClient.Legacy.dll"
```

核心类：`A.c3795a089d76f103f11c4fe70f38ac8ca`（约 5200 行，云端操作层）

**关键前置类型**（都能公开构造）：

### 5.5 通用反射桥

`nutstore_bridge(script)` —— 让插件侧在不改钩子的前提下调用客户端实现。
**加能力先用它验证，再固化。**

脚本一行一个操作，`|` 分隔，行号即槽位号，后续行用 `#N` 引用：

```
NEW|类型全名|参数...          构造
CALL|类型全名|方法名|参数...   静态调用
INSTANCE|槽位|方法名|参数...   实例调用
GET|槽位|成员名               取属性或字段
CHAIN|槽位|成员名|成员名...    沿成员链取
ENUM|类型全名|成员名
```

参数：`s:<base64>` 字符串、`l:<数字>`、`i:<数字>`、`b:true/false`、
`#<槽位>`、`-` null、无前缀按字符串。

**两道安全限制（实测生效）**：只允许客户端自己的程序集
（`System.IO.FileInfo` 被拒）、危险方法名一律拒绝（`RemoveSandbox` 被拒）。

## 六、踩过的坑（按被坑的次数排序）

| 坑 | 症状 | 解法 |
|---|---|---|
| **类型名/方法名是哈希** | 搜不到 = 以为没这能力 | 反编译看调用链 |
| **net48 没有 `string.Contains(string, StringComparison)`** | 编译报错 | 用 `IndexOf` |
| **重载方法不能用不带类型的 `GetMethod(name, flags)`** | `AmbiguousMatchException` | 按参数类型或参数个数取 |
| **`JsonElement` 只在 `JsonDocument` 存活期间有效** | using 外使用读到已释放内存 | 在 using 内提取成普通值 |
| **`Assembly.GetEntryAssembly()` 在非默认域返回 null** | 客户端静态类初始化失败 | 必须回默认域 |
| **只扫 `*.dll` 会漏掉主 exe 里的类型** | 搜不到 = 以为没这能力 | 枚举时加上 `NutstoreClient.exe` |
| **git commit 中文消息里的 `/`、引号会被当成路径** | 提交失败 | 用 `-F <文件>` |
| **客户端 bean 有属性/字段两种风格** | 只找属性会静默拿到 null | 先找属性再找字段 |
| **`SetValue` 只赋字段不触发通知** | 改了值但不生效 | 走 `Value` 属性 setter |
| **客户端管理它认为属于自己的目录** | 建在 `Nutstore\1\*` 下的目录被清理 | 测试目录放外面 |

### 用调用点登记表守住哈希调用

`ClientCallSites` 登记每一个哈希调用点，写清「改不改状态」和「为什么安全」。
**禁止清单是按名字匹配的，挡不住哈希调用** —— 所以需要这份登记。

新增哈希调用而没登记，就是一次需要被审查的改动。
