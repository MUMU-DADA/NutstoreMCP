# 交接说明

先读本文件，再读 [开发计划](开发计划.md)、[客户端能力盘点](客户端能力盘点.md) 和 [调试验证记录](调试验证记录.md)。最后更新：2026-10-09。

## 一、项目与硬约束

把坚果云桌面客户端的能力做成 MCP 工具。插件在独立 AppDomain 可热重载，UI 钩子在客户端默认域取得 WPF 和活服务，开关使用客户端自己的设置界面。

- **绝不导致数据丢失。** 这是用户明确约束，优先于能力覆盖率。
- **只用客户端自己的实现和已登录会话。** 不申请第三方凭据，不另做登录。
- **修改类实验只用新建目录和文件。** 不修改原有云端或本地数据。
- **先用桥验证，再固化专用接口，多个钩子修改合并一次重启。** 尽量减少重装和重启。

## 二、修改类调试注意事项

### 2.1 靶子与绑定边界

现有专用沙箱 `mcp-test`：ID `<sandbox-id>`，magic `<magic>`。客户端实测绑定根为 `%USERPROFILE%\Nutstore\1\mcp-test`。只在这个已有绑定内添加本次全新对象进行写实验。

新建外部本地靶子、下载目标和未来新绑定目标使用 `%USERPROFILE%\NutstoreTest\*`。**不要在客户端管理的 `Nutstore\1` 树下再新建绑定目标**：此前客户端曾清理其中的目录。现有已确认绑定和新绑定目标是两件事。

只读引用已有文件允许。测试产物保留；不要自动删除，也不要为了清理调用删除 MCP。

### 2.2 三重锁和专用前后校验

```
未解锁         → 拒绝
没有 confirm   → 拒绝
dryRun（默认） → 预演，不执行
提交前         → 读取真实绑定、父目录、对象版本和冲突
提交后         → 默认域与插件分别只读核对结果
```

普通令牌：`%LOCALAPPDATA%\NutstoreMcp\l3-write.enabled`，内容必须为 `yes`。系统级设置额外需要 `l3-write-system.enabled`。实验脚本不得覆盖已有令牌；本次用 `FileMode.CreateNew` 建令牌，并在 `finally` 只移除自己创建的令牌。最终已确认没有残留 `l3-write*.enabled`。

移动/建目录工具拒绝无法唯一确认的沙箱 ID/magic、真实本地绝对绑定路径、非规范云端路径和不完整目录结果。云端路径不能有遍历、反斜杠、双斜杠或非法段；冲突比较包含大小写别名，详情路径和 Base64 哈希按大小写精确比较。

移动仅支持普通未删除文件：默认域提交前再次检查源版本、大小、哈希未变，目标仍不存在、父目录仍存在。目录移动未实现。

`attempted=true` 仅表示尝试调用。`executed=true` 要求钩子确认、钩子验证和插件写后复查均成功。失败或未知结果只复查，**不自动重试、不自动回滚、不清理冲突目标**。

### 2.3 删除禁用，ACL 修改仍不执行

插件 `ForbiddenClientMethods` 与桥共用 14 条禁止方法，特别包括：

- 删除对象 `cd9ad552f9198292967c88e3266e162cc` 的两个重载。
- 删除沙箱 `cc62a4576fdf6f6721f7496c5b2d04e30`。
- `MakeDeleteSandboxRequest`，防止经桥拼装删除请求。

ACL 写会改变访问权，需要独立保护设计；本轮只实现 ACL 读取。动态假客户端已验证桥 `CALL/INSTANCE` 的 84 个拒绝场景和 43 个对象边界场景，禁止方法调用计数为 0。

### 2.4 失败也要看真实状态

旧目录移动入口曾在空元数据集合时抛 `ArgumentException`，当时文件未动；这不能推导其他失败都无副作用。本轮用新哨兵验证真实文件移动与建目录的冲突，客户端返回 `DuplicateName/Conflict`，哨兵版本、大小、哈希保持不变。详细证据见验证记录。

## 五、基础设施与常用命令

### 5.1 部署与重启

默认域的 .NET Framework 程序集不能卸载，新增钩子方法需要重启。桥实验和插件侧变化可先完成，再一次性固化钩子。

```powershell
.\verify.ps1
.\deploy\build.ps1
.\deploy\restart-client.ps1
dotnet run --project src/NutstoreMcp -- --doctor
dotnet run --project src/NutstoreMcp -- --dump-config-keys
```

`verify.ps1` 现在是逐项目 `--no-restore` 构建，主测试和探针都带超时（受限环境里 HTTPS 不通时，解决方案级 `dotnet build` 只会回一句「0 个错误」，而挂起的测试会让整轮验证永远停住）。唯一必须**在沙箱外**跑的一步是配置补丁自测：它用 `File.Replace` 原子替换，文件沙箱会拒绝该 API，脚本会明确提示。

`restart-client.ps1` 先停 watchdog，安装提权是异步的，按程序目录契约轮询安装完成，再通过计划任务在 DSH 沙箱外启动，等待后复查存活。**加新钩子方法时同步更新脚本 `$required` 清单**，避免旧契约被当成安装成功。

MCP：`http://127.0.0.1:17321/mcp`。

### 5.2 混淆常量与升级校验

集中源：`src/NutstoreMcp.ClientBindings/ClientSymbols.cs`，含 23 个混淆常量（54 个符号常量）和共 82 项登记，包括 D1 调查入口、辅助成员与枚举；用源码 link 编译，避免新增运行依赖。版本基线位于同目录 `baseline-7.2.12-events-transport.json`，更新流程见该目录 README。

检查器：`recon/ClientBindingCheck`，只读 PE 元数据与 IL，校验完整重载、方法体、程序集 SHA/MVID/版本、枚举和预期数值。运行 `.\deploy\check-client-bindings.ps1`；当前安装版 7.2.12.0 已通过。构建、安装和重启前自动检查，差异须重新审查语义，不能直接刷新基线放行。显式 `--record` 仅新建基线、不覆盖。

桥与插件共用 14 项危险方法；桥还限制实例/属性链的接收者和成员声明，只认客户端程序集，拒绝反射/委托对象和 `NutstoreMcp.*` 自调用。离线 84 个禁止变体、43 个边界场景通过。System 集合可作输出槽位，但不能以 INSTANCE/GET/CHAIN 操作；使用专用工具导出此类信息。

### 5.3 反编译与桥

```powershell
ilspycmd -p -o <输出目录> "C:\Program Files\Nutstore\bin-7.2.12\NutstoreClient.Legacy.dll"
```

核心类：`A.c3795a089d76f103f11c4fe70f38ac8ca`。类型名/方法名都是哈希，语义必须读调用链，不能仅由参数/返回类型猜测。

前置类型：`SandboxIdentifier(id,magic)`、`NSSandbox(id,magic,localAbsPath,allowUncPath)`、`SandboxACL.GetDefaultPerm()`、`NutstorePath.FromNutstorePath` / `FromAbsolutePath`。

桥脚本一行一操作，`|` 分隔，后续用 `#N` 引用槽位：

```
NEW|类型全名|参数...
CALL|类型全名|方法名|参数...
INSTANCE|槽位|方法名|参数...
GET|槽位|成员名
CHAIN|槽位|成员名|成员名...
ENUM|类型全名|成员名
```

参数支持 `s:<base64>`、`l:<数字>`、`i:<数字>`、`b:true/false`、`#<槽位>`、`-` null。桥只允许客户端程序集，危险方法拒绝；不要把它当作已有写工具的守卫替代品。

## 六、已验证的坑

| 坑 | 症状 | 处理 |
|---|---|---|
| 混淆方法被猜成只读 | D4 bool 返回值被误判状态查询 | 读完整请求/落库调用链，登记副作用 |
| 目录入口误用于文件移动 | 空集合抛 `ArgumentException` | 文件用 `cfa4...`，保留版本/大小/哈希 |
| `string.Contains(string,StringComparison)` 不支持 net48 | 编译失败 | 使用 `IndexOf` |
| 重载 `GetMethod` 未带参数类型 | `AmbiguousMatchException` | 按完整签名或参数约束取方法 |
| `JsonElement` 超出所属文档生命周期 | 已释放对象访问 | 在文档内提取普通值 |
| 非默认域 `GetEntryAssembly()` 为 null | 客户端静态初始化失败 | 返回默认域调用 |
| 只扫 DLL | 漏掉主 EXE 类型 | 同时扫描 `NutstoreClient.exe` |
| bean 字段/属性风格不同 | 读出 null | 属性和字段均支持 |
| `SetValue` 不触发通知 | 值变了但不生效 | 走 `Value` setter |
| 在 `Nutstore\1` 内新建绑定目标 | 目录被客户端清理 | 外部目标使用 `NutstoreTest\*` |
| Base64 哈希按不区分大小写比较 | 不同哈希可能被认为相同 | 哈希与详情路径用 `Ordinal` |
| 传输层异常没被翻译 | `--doctor` 崩在未处理 `HttpRequestException`，MCP 工具只剩通用错误 | 在发请求处一次性转 `NetworkException`（`NETWORK_ERROR`） |
| 只读 stdout、不读 stderr | 子进程写满 stderr 管道即阻塞，测试挂到超时而不是失败 | 两个流并发读，断言消息带 stderr |
| 受限环境里 MSBuild 报「失败 / 0 个警告 0 个错误」 | 看不出原因，像代码坏了 | 解决方案构建先跑 Restore（HTTPS 不通即失败）→ 逐项目 `--no-restore`；跨项目引用走并行节点命名管道 → 加 `-m:1` |
| `Process.ExitCode` 在受限环境返回空 | 子进程成败判不出来 | 解析子进程自己打印的结论行，别看 ExitCode |

`ClientCallSites` 保留目的、副作用和安全理由；禁止清单还需直接包含已确认危险的混淆哈希。新增调用点和集中常量后都要进行升级校验。
