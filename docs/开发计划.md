## 一、总体目标

把坚果云桌面客户端**只能在 GUI 上操作**的能力做成 MCP 工具。

**两条硬约束**：

1. **数据安全优先** —— 绝不导致数据丢失。写操作必须有多重守卫，
   破坏性操作宁可不做。
2. **只用客户端自己的实现** —— 不引入需要申请第三方凭据的接口（如 WebDAV 应用密码），
   否则违背「装上插件就能用」的初衷。

## 二、基础设施

- [x] 插件以 mod 形式放进程序目录即生效
- [x] 插件在独立 AppDomain 运行（可热重载，不用重启客户端）

- [x] 桥通过 `appDomainManagerAssembly` 注入（.NET 官方扩展点，在 `Main` 之前运行）
- [x] 跨域只通过共享契约程序集通信
- [x] MCP over Streamable HTTP（`http://127.0.0.1:17321/mcp`）
      —— GUI 进程做不了 stdio
- [x] 插件开关做进客户端自己的设置界面（用它自己的 `SettingItem` 控件）
- [x] 配置补丁原子写入 + 写前校验 + 失败可用备份还原
- [x] 客户端目录发现按**版本号**排序（字符串排序会让 `bin-7.2.9` 排在 `bin-7.2.13` 之后）

      .NET 编译不可字节复现）
- [x] 一键验证脚本 `verify.ps1`（构建 + 测试 + 探针 + 配置补丁自测）
- [x] 停止 / 重装 / 重启客户端的一体化脚本 `deploy/restart-client.ps1`

## 四、安全机制

### 4.1 写入守卫（绑定 / 建文件夹）

- [x] 三重锁：解锁令牌 + `confirm=true` + `dryRun` 默认 `true`
- [x] 非空本地目录一律拒绝（核心数据安全）
- [x] 嵌套同步根拒绝（含大小写不敏感的 6 种边界）
- [x] 缺沙箱状态时 fail-closed
- [x] 已绑定的沙箱拒绝重绑
- [x] 解锁令牌内容必须是 `yes`（空文件不解锁）
- [x] 令牌用完即删，实测确认回到锁定

### 4.2 设置写入的两把锁

- [x] 普通开关：`l3-write.enabled`
- [x] **系统级设置额外需要 `l3-write-system.enabled`**
      —— 共用一把锁的话，「为了改开机自启而解锁」就等于同时允许装驱动
- [x] 白名单制，不接受任意属性名
- [x] 端到端验证：只有普通令牌时改 `EnableFileProtectionLock` 被拒

### 4.3 禁止调用清单

- [x] 9 条危险客户端方法（`RemoveSandbox`、`MigrateSandboxPath`、
      `UnregisterAllNutstoreSyncRoots` 等）
- [x] **发现缺口**：清单是按**名字**匹配的，而混淆方法名是哈希 ——
      名字匹配对它们完全无效
- [x] 补上登记制：`ClientCallSites` 登记每一个哈希调用点，写清「改不改状态」和「为什么安全」

### 4.4 报告真实状态

- [x] 写完之后比对值是否等于目标，不等就明确报「客户端可能拒绝了这次改动」
- [x] 设置没落盘时明说「重启后会变回去」
- [x] 钩子版本不匹配时优雅报告，不崩溃不静默

### B. 文件内容

- [x] B1 **下载文件内容**（已落地并验证） `c089b7574cb46db5e6d9bba4e0e0a6002(...) → Stream`
      —— **参数语义已用桥实测清楚，未固化成专用方法**。

      签名：(NutstorePath path, long localVersion, long remoteVersion,
             ref bool downloadFull, GetRange range, bool acceptDelta)

      **实测结论**（四组对照）：

      | localVersion | remoteVersion | range | 结果 |
      |---|---|---|---|
      | 0 | 0 | null | `ObjectNotFound: the Object 不存在` |
      | 0 | -1 | null | `IllegalArgument: Object version is not valid` |
      | 0 | **1**（真实版本） | null | ✅ 返回 `ReadWriteTimeoutSafeStream`，ref bool 写回 `False` |

      **所以 remoteVersion 必须是真实版本号**，不能传 0/-1 表示「最新」。
      最新版本号从 A9（对象详情）的 `version` 字段取 —— 两步配合即可。

      `GetRange(0,0)` 会被客户端拒绝（`0 vs 0`），传 null 表示整文件。
      ref bool 的输出 `False` = 本次拿到的是全量、不是增量。

      **已落地**：`nutstore_l3_download(sandboxId, magic, cloudPath, destPath,
      confirm, dryRun)` —— 落盘到本地路径，不回传内容。

      三道守卫实测：未解锁拒绝 / 目标已存在拒绝覆盖 / 全新目标成功
      （775804 字节，与云端对象详情报的大小逐字节一致）。

      写入用 `FileMode.CreateNew` —— 即使「判断不存在」和「真正写入」
      之间被抢先建了文件，也只会抛异常，不会覆盖。

### 6.2 通用桥 与 专用接口（用户定的原则）

**通用分发只是过渡，专用接口才是最终形态。**

工作流因此变成：

1. **用桥验证**能力 —— 不改钩子，不重启
2. 验证通过后**固化成专用方法**（有名字、有类型、有文档）
3. **多个固化合并成一次重启** —— 而不是一个能力一次

桥本身有两条限制（已实测生效）：
· 只允许客户端自己的程序集 —— `System.IO.FileInfo` 这类被拒绝，
  不能拿它当通用 .NET 执行器
· 危险方法名一律拒绝 —— `RemoveSandbox` 被拒绝

已固化：A3 A4 A5 A6 A7 A8（各有专用方法）。
待固化：用桥验证过的那些。

## 六·五、写操作的测试策略（用户定的）

**涉及修改的操作，一律用新建的目录和新文件做靶子，
不动云端和本地原有的目录和文件。**

· 云端靶子：新建的沙箱（如 `mcp-test`）
· 本地靶子：新建的目录（如 `%USERPROFILE%\NutstoreTest\*`）
· 只读地引用已有文件是允许的 —— 读不改东西
