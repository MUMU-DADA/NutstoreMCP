## 能力开放路线（2026-10-18 复核修订）

原「已查清并否决」七条复核后：**三条**可按新的约束方式开放（P0 空文件、P1 已有目录创建、P3 改元数据）、**两条**部分开放（仅对象删除、仅分享 E1）、**两条**维持不动（C5 恢复、设置白名单之外）。P0/P1/P2/P3 已落地、P4 已实现（2026-10-19）。

**共同原则：测试只能学语义，不能替代约束。** 用自家靶子测出「会发生什么」是正确的，也是唯一允许的测法；但它不等于生产环境安全 —— 每次真实调用仍可能撞上用户已有的同名或大小写别名对象，安全性必须来自结构限制：两端预检 + 目标全新 + 写后复查 + 破坏性操作限定在台账内。

实现顺序：**P0 → P1 → P2 → P3 → P4 已全部落地（2026-10-19）**；P4 的执行路径在线受账号等级限制，代码与离线验证已完成。

### P0 空文件创建（已完成 2026-10-18）

- 配方（反编译 + 在线验证）：云端 hash = 32 个零字节；跳过内容上传；`fullObjectNameBase64 = null`；`blockListNameBase64 = Base64(40 个零字节)`。
- 参数表达：`contentBase64=""` 即空文件，不新增工具；本地 0 字节文件仍被读取策略拒绝并提示改走内联。
- 实现：插件按「内容长度 0」如实传给默认域；钩子走空文件分支；写后仍核对类型、大小 0、云端 hash、版本与父目录成员。
- 离线验证：主测试 286 项（新增 3 项：空文件成功、空文件写后哈希不符、32/40 零字节常量），`verify.ps1` 全绿。
- 在线验证：在 mcp-test 沙箱新建目录 + `empty.txt`，`executed=true`、`contentUploaded=false`、`size=0`、`cloudHash=Base64(32 零字节)`、version=1；`object_detail` / `list_cloud_dir` / `read_file` 回读一致（`integrity=empty`），客户端把 0 字节文件同步到了本地绑定目录。

### P1 任意已有目录里创建文件（已完成 2026-10-18）

原缺口：`nutstore_l3_create_file` 只允许父目录由本次调用新建，等于每写一个文件都要先建一个新目录。现新增 `directoryPath` 模式（与 `directoryName` 二选一）。

- **两端预检**：云端父目录全量列举 **+ 本地绑定文件夹枚举**，任一大小写等价即拒；父路径逐字符核对（云端详情回读 + 本地逐段大小写）；本地枚举失败、父路径是文件、成员超过 100 项一律拒绝。
  理由：客户端的冲突改名/删除分支同样会在本地触发，只查云端不足以排除对本地真实文件的副作用。
- **提交前复查**：钩子在上传内容后、提交元数据前再只读确认目标仍不存在（含大小写别名）、父目录仍有效。根路径的详情客户端拒绝查询（`You cannot query the full info of root path`），根下创建只做列表检查。
- **写后三重复查**：父目录恰好 +1 项且其余成员路径/类型/版本/哈希未变 → 目标大小/云端 hash/版本 → 按 256 KiB 分段把云端字节整文件读回并核对 SHA-256。任何不符：停止、只报告、不重试、不回滚。
- **残余风险（已按复核默认接受）**：预检与发布之间的并发窗口（服务端无大小写原子去重）；由写后复查发现并如实报告。
- 离线验证：主测试 313 项（新增 27 项：成功/拒绝/并发副作用/回读不符/两种模式与本地探针），`verify.ps1` 全绿。
- 在线验证：子目录 `/p0-empty-20261018-2325` 内创建 `hello.txt`（1.2 秒）：`membersUnchanged=true`、`readBackMatches=true`、`memberCountBefore=After=1`；沙箱根下创建（28 个既有成员，5.7 秒）：快照前后一致、回读 SHA-256 一致；精确同名与大小写别名（`HELLO.TXT`、`Hello.Txt`）均被拒且未写入；已有目录里的空文件同样成功（回读 SHA-256 = 空内容摘要）；客户端把新文件同步到了本地绑定目录。

### P2 台账限定删除（已完成 2026-10-18）

- 只删得掉 MCP 自己创建的对象：插件维护 `%LOCALAPPDATA%\NutstoreMcp\created-objects.jsonl`（path / version / size / hash / 时间 / 来源工具 / 内容来源；成功删除后追加 `action=deleted` 记录），删除要求当前详情的 version、大小与 hash 与最后一条 created 记录完全一致。
- 收益：首次获得「撤销自己刚写入的东西」的能力，并可清理测试沙箱遗留的探针对象。
- 安全相关重构：删除对象的混淆入口**没有从禁止清单移除**，而是新增 `dedicated-only` 概念 —— 通用桥与反射工具仍然拒绝它（`ForbiddenClientMethods.Check` 不变），只有专用钩子路径经独立契约方法 `DeleteCloudObject` 调用；客户端契约因此更新一次（UAC 安装）。
- 新增风险面：台账被篡改即等于任意删除。补「路径必须落在当前已绑定沙箱内 + 拒绝通配/根路径 + 台账路径逐字符一致（大小写别名拒绝）+ 当前详情版本/大小/hash 必须匹配」的二次校验。
- 仍不做：删除沙箱、解绑、迁移同步根（动的是账号与设备结构，不是文件对象）。
- 离线验证：主测试 343 项（新增 30 项：台账读写/坏行/大小写、删除成功/预演/拒绝/钩子失败/清理失败/台账写失败、专用放行边界），`verify.ps1` 全绿。
- 在线验证：创建 `delete-test-*.txt` 后 `ledgerRecorded=true`；预演只读；执行删除 0.5 秒 `executed=true`、`detailAfter=deleted`、`targetPresent=false`、台账追加 deleted，本地绑定目录里的文件同步消失；重复删除、非台账对象（`hello.txt`）、大小写别名（`LedgerCase`→`ledgercase`）均被拒绝且对象未动。

### P3 修改文件当前版本（C4，已完成 2026-10-19）

- 修正此前判断：C4 产生新版本、旧版本进历史，因此「覆盖」并非不可逆（网页端可回退）。真实风险是：当前版本被写成错误内容、内容引用传错导致新版本指向别的字节、以及并发窗口。
- 门控（全部落地）：目标由调用方显式给出 → 预演展示「当前版本 vs 新字节」差异 → 执行必须带 `expectedVersion`（二次确认令牌）→ **第一版仅允许台账内、且自创建以来未被改动过的对象** → 写后核对新版本/大小/hash、整文件回读 SHA-256、历史版本保留 → 返回中说明网页端回退方法。
- 服务端 CAS：没有在不绕过守卫的情况下直接观测（预检与提交前复查都会先挡住版本变化）；保证由「插件核对台账 + 钩子提交前紧邻复查版本」承担，属 fail-closed。
- 与 C5 不对称：C4 能做、C5 不做 = 能改坏，但旧版本在历史里，可以在网页端回退；本次不排期 C5。
- 离线验证：主测试 375 项（含修改的 15 项守卫用例：预演/成功/台账缺失/已修改/状态漂移/错误版本/钩子失败/写后版本未变/回读不符/历史缺旧版本/内容边界/未解锁）。
- 在线验证：台账内文件 v1→v2（0.9 秒）：`executed=true`、`versionAfter=2`、`contentMatches=true`、`readBackMatches=true`、`historyHasPrevious=true`、`ledgerRecorded=true`；`file_versions` 显示 v2「编辑」29 B 与 v1「创建」12 B；`read_file` 读到新内容（`integrity=verified`），本地同步更新；重复修改（台账已 modified）与错误 `expectedVersion` 均被拒。

### P4 分享（仅 E1 公开链接，已实现 2026-10-19；在线受账号等级限制）

- 修正此前判断：客户端接口不能取消分享，但**网页端能撤**，不是永久不可逆。
- 真正的红线：分享 URL 本身是访问凭证（客户端自家 Outlook 插件会把它写进外发邮件），一旦作为返回值即进入对话与日志。
- 门控（全部落地）：默认预演 → confirm → 执行，禁止被自动触发；支持有效期/密码/禁下载；**目标已有分享时拒绝**（第一版只创建、不覆盖既有设置）；URL 仅在显式 `returnUrl=true` 时返回并标注为凭证；分享台账 `%LOCALAPPDATA%\NutstoreMcp\shares.jsonl` 只存 URL 的 SHA-256 与设置快照。
- **在线结果（2026-10-19）**：预演正常；执行被服务端拒绝 `RequestException (DisabledForFreeUser)` —— 当前是免费账号，公开分享需要付费账号。**无副作用**：分享状态仍为「未分享」、`shares.jsonl` 未创建、工具如实报告失败。URL 隐藏/凭证标注/台账只存哈希/已有分享拒绝等路径由离线测试覆盖；拿到付费账号后可直接复测执行路径。
- 不做：E2 邮件分享（真发信、无撤销）、E3 ACL 写（全量替换整棵子树、绕过 GUI 的 `HasManageCap`）、E5 快捷方式（留下删不掉的 `.nslink`）、团队文件。

### 继续不开放

| 能力 | 原因 |
|---|---|
| 删除沙箱 / 解绑 / 迁移同步根 | 不可逆，动账号与设备结构 |
| E2 邮件分享 / E3 ACL 写 | 无撤销或绕过 GUI 门禁，不可逆地扩大访问权 |
| E5 云端快捷方式 / 团队文件 | 留下无法删除的对象，价值不足 |

## 维护与交接

- 测试沙箱：`mcp-test`（ID/magic 运行期从 `nutstore_l3_sync_folders` 取，仓库只写 `<sandbox-id>`/`<magic>` 占位符）。
- 部署：日常改插件跑 `.\deploy\build.ps1`（热重载）；改钩子/契约跑 `.\deploy\restart-client.ps1`（可能需要 UAC）；首次安装见 [deploy/README.md](../deploy/README.md)。**改契约时顺序必须是先 `build.ps1`（把新插件/新钩子同步到新 plugin 目录并改 bridge.ini）再 `restart-client.ps1`**：反过来的话，安装完契约后客户端会先用「旧契约编译的旧钩子」启动，钩子挂不上（`uiHookAttached=false`，所有能力返回 `available:false`），需要再重启一次客户端才能恢复。
- 写入调试：创建 `%LOCALAPPDATA%\NutstoreMcp\l3-write.enabled`（内容 `yes`），调试完删除；本地文件创建另需 `read-roots.txt`。
- 测试产物保留：默认不删除；需要清理 MCP 自己创建的对象时用 `nutstore_l3_delete_created_object`（台账限定），不因「是测试文件」自动获得删除授权。台账文件：`%LOCALAPPDATA%\NutstoreMcp\created-objects.jsonl`（创建/修改/删除记录；删除它只是撤销删除/修改授权，不会影响云端对象）。
- 分享：`nutstore_l3_publish_share` 默认预演；台账 `%LOCALAPPDATA%\NutstoreMcp\shares.jsonl` 只存 URL 的 SHA-256，**链接原文不入库**；撤销需在网页端；免费账号的公开分享会被服务端拒绝（`DisabledForFreeUser`）。
