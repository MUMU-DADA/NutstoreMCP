## 一、总体目标

把坚果云桌面客户端**只能在 GUI 上操作**的能力做成 MCP 工具。

**两条硬约束**：

1. **数据安全优先** —— 绝不导致数据丢失。写操作必须有多重守卫，
   破坏性操作宁可不做。
2. **只用客户端自己的实现** —— 不引入需要申请第三方凭据的接口（如 WebDAV 应用密码），
   否则违背「装上插件就能用」的初衷。

## 二、基础设施

- [x] 插件以 mod 形式放进程序目录即生效
- [x] 插件在独立 AppDomain 运行（可热重载，不用重启客户端）
- [x] UI 钩子跑在客户端默认域（WPF 对象和活服务都在那）
- [x] 桥通过 `appDomainManagerAssembly` 注入（.NET 官方扩展点，在 `Main` 之前运行）
- [x] 跨域只通过共享契约程序集通信
- [x] MCP over Streamable HTTP（`http://127.0.0.1:17321/mcp`）
      —— GUI 进程做不了 stdio
- [x] 插件开关做进客户端自己的设置界面（用它自己的 `SettingItem` 控件）
- [x] 配置补丁原子写入 + 写前校验 + 失败可用备份还原
- [x] 客户端目录发现按**版本号**排序（字符串排序会让 `bin-7.2.9` 排在 `bin-7.2.13` 之后）
- [x] 契约两处部署的一致性检查（比对接口方法清单，不是比对文件哈希 ——
      .NET 编译不可字节复现）
- [x] 一键验证脚本 `verify.ps1`（构建 + 测试 + 探针 + 配置补丁自测）
- [x] 停止 / 重装 / 重启客户端的一体化脚本 `deploy/restart-client.ps1`

## 四、安全机制

### 4.1 写入守卫（绑定 / 建文件夹）

- [x] 三重锁：解锁令牌 + `confirm=true` + `dryRun` 默认 `true`
- [x] 非空本地目录一律拒绝（核心数据安全）
- [x] 嵌套同步根拒绝（含大小写不敏感的 6 种边界）
- [x] 缺沙箱状态时 fail-closed
- [x] 已绑定的沙箱拒绝重绑
- [x] 解锁令牌内容必须是 `yes`（空文件不解锁）
- [x] 令牌用完即删，实测确认回到锁定

### 4.2 设置写入的两把锁

- [x] 普通开关：`l3-write.enabled`
- [x] **系统级设置额外需要 `l3-write-system.enabled`**
      —— 共用一把锁的话，「为了改开机自启而解锁」就等于同时允许装驱动
- [x] 白名单制，不接受任意属性名
- [x] 端到端验证：只有普通令牌时改 `EnableFileProtectionLock` 被拒

### 4.3 禁止调用清单

- [x] 9 条危险客户端方法（`RemoveSandbox`、`MigrateSandboxPath`、
      `UnregisterAllNutstoreSyncRoots` 等）
- [x] **发现缺口**：清单是按**名字**匹配的，而混淆方法名是哈希 ——
      名字匹配对它们完全无效
- [x] 补上登记制：`ClientCallSites` 登记每一个哈希调用点，写清「改不改状态」和「为什么安全」

### 4.4 报告真实状态

- [x] 写完之后比对值是否等于目标，不等就明确报「客户端可能拒绝了这次改动」
- [x] 设置没落盘时明说「重启后会变回去」
- [x] 钩子版本不匹配时优雅报告，不崩溃不静默
