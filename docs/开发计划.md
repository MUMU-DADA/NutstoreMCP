## 能力开放路线（2026-10-18 复核修订）

原「已查清并否决」七条复核后：**三条**可按新的约束方式开放（P0 空文件、P1 已有目录创建、P3 改元数据）、**两条**部分开放（仅对象删除、仅分享 E1）、**两条**维持不动（C5 恢复、设置白名单之外）。

**共同原则：测试只能学语义，不能替代约束。** 用自家靶子测出「会发生什么」是正确的，也是唯一允许的测法；但它不等于生产环境安全 —— 每次真实调用仍可能撞上用户已有的同名或大小写别名对象，安全性必须来自结构限制：两端预检 + 目标全新 + 写后复查 + 破坏性操作限定在台账内。

实现顺序：**P0 → P1 → P2 → P3 → P4**（P2 是安全相关重构，独立排期）。

### P0 空文件创建（无风险，先做）

- 配方已从反编译取得：云端 hash = 32 个零字节；跳过内容上传；`fullObjectNameBase64 = null`；`blockListNameBase64 = Base64(40 个零字节)`。
- 实验沿用现有「本次新建空目录 + 全新文件名」流程，建后回读 `size=0`。
- 读侧无需改动：详情 `size=0` 已直接返回空结果。空目录作为 flag 已有 `nutstore_l3_mkdir`，不新增工具。

### P1 任意已有目录里创建文件（当前最大可用性缺口）

现状：`nutstore_l3_create_file` 只允许父目录由本次调用新建，等于每写一个文件都要先建一个新目录。

开放前提是**两端预检**（此前遗漏本地一侧）：

- 云端父目录全量列举 **+ 本地绑定文件夹全量列举**，任一大小写等价即拒；列举被截断即拒；父路径本身不得是别名。
  理由：客户端的冲突改名/删除分支同样会在本地触发，只查云端不足以排除对本地真实文件的副作用。
- 提交元数据前紧邻时刻再只读确认一次（复用现有 fresh-dir 路径的模式）。
- 写后三重复查：父目录恰好 +1 项且其余成员版本/哈希未变 → 目标大小/哈希/版本 → 下载回读字节。任何不符：停止、只报告、不重试、不回滚。
- 残余风险：预检与发布之间的并发窗口（服务端无大小写原子去重，已实测确认）。**待拍板**是否接受；不接受则只开「纯数字无扩展名文件名」窄档（结构上无别名，已验证）。

### P2 受限删除（台账限定）

- 只删得掉 MCP 自己创建的对象：插件维护 `%LOCALAPPDATA%\NutstoreMcp\created-objects.jsonl`（path / version / hash / 时间 / 来源工具），删除要求当前详情的 version 与 hash 完全匹配。
- 收益：首次获得「撤销自己刚写入的东西」的能力，并可清理测试沙箱遗留的探针对象。
- 成本：需从 `ForbiddenClientMethods` 移出删除入口，桥允许清单、84 项绑定、283 项测试同步改 —— 属安全相关重构，单独排期。
- 新增风险面：台账被篡改即等于任意删除。补「路径必须落在当前已绑定沙箱内 + 拒绝通配与大小写别名」的二次校验。
- 仍不做：删除沙箱、解绑、迁移同步根（动的是账号与设备结构，不是文件对象）。

### P3 修改文件元数据（C4，先实验）

- 修正此前判断：C4 产生新版本、旧版本进历史，因此「覆盖」并非不可逆（网页端可回退）。真实风险是：当前版本被写成错误内容、服务端无 CAS 时的并发怪版本、内容引用传错导致新版本指向别的字节。
- 实验使用自家对象，先确认：version 语义、服务端是否做 CAS、写后历史中旧版本是否保留。
- 门控：目标由用户显式给出 → 预演展示「当前版本 vs 新字节」差异 → 二次确认令牌 → 第一版仅允许台账内对象 → 写后复查 version/哈希/大小，返回中说明网页端回退方法。
- 与 C5 不对称：C4 能做、C5 不做 = 能改坏但不能自己改回来。**待拍板**是否把 C5 同沙箱恢复一并做（随机源 + 全新目标 + 单次调用）形成闭环。

### P4 分享（仅 E1 公开链接）

- 修正此前判断：客户端接口不能取消分享，但**网页端能撤**，不是永久不可逆。
- 真正的红线：分享 URL 本身是访问凭证（客户端自家 Outlook 插件会把它写进外发邮件），一旦作为返回值即进入对话与日志。
- 门控：默认预演 → confirm → 执行，禁止被自动触发（分享是提示注入的头号目标）；支持有效期/密码/禁下载；URL 仅在显式参数时返回并标注为凭证；建立分享台账便于事后核对与撤销。
- 不做：E2 邮件分享（真发信、无撤销）、E3 ACL 写（全量替换整棵子树、绕过 GUI 的 `HasManageCap`）、E5 快捷方式（留下删不掉的 `.nslink`）、团队文件。

### 继续不开放

| 能力 | 原因 |
|---|---|
| 删除沙箱 / 解绑 / 迁移同步根 | 不可逆，动账号与设备结构 |
| E2 邮件分享 / E3 ACL 写 | 无撤销或绕过 GUI 门禁，不可逆地扩大访问权 |
| E5 云端快捷方式 / 团队文件 | 留下无法删除的对象，价值不足 |
| 修改客户端设置白名单之外 | 可改坏客户端配置且难以解释 |
| C5 恢复历史版本 | 维持「只保留隔离实验」；是否随 P3 一并做见待拍板 |

## 可选后续

已进入路线的项（P0–P4）不再列在此处。仍未排期：

1. **F1 文件锁**：若确需，只对本次新建文件、用 F1 解锁（禁用 F2）、失败即停。
2. **C5 同沙箱恢复/复制**：若 P3 要形成「能改也能改回来」的闭环，则随之排期；只做同沙箱、随机源 + 全新目标、单次调用。
3. **大文件扩展**：评估把 16 MiB 上限提高、接入 DEFLATE 压缩分支。
4. **事件保留期**：需等最早事件过期才能确定；当前已知下限 ≥ 9 天。
5. **L2 类本地只读能力**（同步状态/错误）如需恢复，应作为插件新工具在默认域实现，不走 WebDAV。
